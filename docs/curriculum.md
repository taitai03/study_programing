## 0. 全体像

| コース | 初級 | 中級 | 上級 |
| --- | --- | --- | --- |
| JavaScript / TypeScript | 7本（ブラウザ） | 10本（PR） | 9本（PR＋AIレビュー） |
| Ruby / Rails | 7本（ブラウザ） | 8本（PR） | 7本（PR＋AIレビュー） |
| Swift | 7本（Playground＋クイズ） | 8本（PR） | 7本（PR＋AIレビュー） |
| 共通: 開発の準備 | 4本（初級と中級の間） | | |

合計 74本。各レッスンは「短い解説 → 演習 → 確認クイズ（3問程度）」で、1本30〜60分を想定する。

### 方針

- **現場で使うものを題材にする**: 演習は「商品」「注文」「タスク」「ユーザー」など、業務アプリでよく出てくるデータを使う
- **中級の最後は小さなアプリを作る**: そのレベルで学んだことをまとめて使う
- **上級は4種類の演習を混ぜる**: 各レッスンの「種類」列に、どの演習形式かを記載する
  - 改善: 問題のあるコードを、テストを通したままリファクタリングする
  - 脆弱性: 脆弱性を含むコードを直す。攻撃を再現するテストで判定する
  - 設計: 仕様から機能を追加し、設計方針をPRの説明に書く
  - レビュー: 用意されたPRをレビューして指摘を書く

### 表の見方

- **学ぶこと**: レッスンで扱う内容
- **演習**: 手を動かす課題の概要
- **判定**: 自動テスト（テスト）、確認クイズ（クイズ）、AIレビュー（AI）のどれで判定するか

## 5. 決定事項

- Railsのテストは **RSpec** を使う（現場で使われることが多いため）
- JS/TSでAPIを作るときは **Next.js の Route Handlers** を使う。画面とAPIを同じフレームワークで学べる
- JS/TSコースで **React / Next.js を扱う**。中級に3本（React の基礎、Next.js で API、画面から API を使う）、上級に1本（フロントエンドの設計）を入れる
- 画面の判定: コンポーネントは React Testing Library でテストし、見た目や構成はAIレビューで確認する
