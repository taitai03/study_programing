# プログラミング学習Webアプリ 要件定義

> ステータス: 要件ヒアリング中（未決事項あり）
> 最終更新: 2026-10-19

## 1. 決定事項

### 1.1 背景

プロジェクトを開始するにあたり、各個人のプログラミング能力と知識を向上させる。

### 1.2 対象者（レベル区分）

| レベル | 定義 |
| --- | --- |
| 初級 | まったく何も学んだことのない初学者 |
| 中級 | 書いてある処理は読めるが、自分の力で書くことはできない |
| 上級 | リファクタリングや安全な設計ができ、プロダクト全体の責任者を目指す |

### 1.3 アプリの内容

- プログラミングを学べる **Webアプリケーション** である
- 上記の対象者（初級／中級／上級）でコンテンツを **ジャンル分け** する
- **実際の現場で使える** 学びを得られる内容にする
- **実際に手を動かしながら** 学べる
- 対象言語は次の3つ
  - Swift
  - JavaScript（TypeScript）
  - Ruby（Rails）

## 2. 未決事項（確認が必要な項目）

回答が決まったものから「1. 決定事項」へ移していく。

### 2.1 利用者・運用

- [ ] 利用者は社内メンバーのみか、社外にも公開するか
- [ ] 想定する利用人数（数人／数十人／それ以上）
- [ ] ログイン機能は必要か（必要なら認証方式: メール＋パスワード／Google／GitHub／社内SSO など）
- [ ] 管理者ロールは必要か（教材の追加・編集、受講者の進捗確認など）
- [ ] 教材を作るのは誰か（開発者がコードで管理／管理画面から非エンジニアも追加）

### 2.2 学習体験（「手を動かす」の具体像）

- [ ] コードの実行方式
  - A. ブラウザ内で実行（JS/TS は可能。Ruby は ruby.wasm、Swift はブラウザ実行が難しい）
  - B. サーバー側のサンドボックスで実行（全言語対応可。インフラとセキュリティのコストが大きい）
  - C. ローカル環境で課題を解き、提出物（GitHubのPRなど）をチェックする
  - D. 上記の組み合わせ（例: 初級はブラウザ内、中級以上はローカル＋PR）
- [ ] 正誤判定の方法（自動テストで判定／正解例との比較のみ／レビュー担当者が確認）
- [ ] Swift（iOS/UIKit/SwiftUI）や Rails（DB・ルーティングなど）の、ブラウザだけでは完結しない内容をどう扱うか
- [ ] 教材の形式（テキスト＋演習／クイズ／動画／ステップ形式のハンズオン）
- [ ] 上級者向けの「設計・リファクタリング」演習の形式（既存コードを渡して改善させる／設計課題にレビューする など）
- [ ] AIによるヒントやコードレビュー機能は必要か

### 2.3 進捗・評価

- [ ] 進捗管理（完了したレッスンの記録、達成率の表示）は必要か
- [ ] レベル判定テストで初級／中級／上級を振り分けるか、本人が選ぶか
- [ ] ランキング、バッジ、修了証などのゲーム要素は必要か
- [ ] 管理者・メンターが受講者の進捗を一覧で見る機能は必要か

### 2.4 コンテンツ量・スコープ

- [ ] 最初のリリース（MVP）に含める範囲（例: 1言語×初級のみ／3言語×初級／全部）
- [ ] 1レベルあたりのレッスン数の目安
- [ ] 教材の初期コンテンツは誰が書くか（開発者側でサンプルを用意する／別途用意される）

### 2.5 技術・インフラ

- [ ] アプリ自体の技術スタックの希望（例: Next.js + TypeScript／Rails／その他）
- [ ] データベースの希望（PostgreSQL／SQLite／Firebase／Supabase など）
- [ ] デプロイ先（Vercel／Render／Fly.io／AWS／社内サーバー／当面はローカルのみ）
- [ ] 予算の制約（無料枠で収める必要があるか）

### 2.6 デザイン・その他

- [ ] デザインの方向性（参考サービス、Figmaのデザインの有無）
- [ ] スマホ対応は必要か
- [ ] UIの言語（日本語のみか）
- [ ] 期限・マイルストーン
