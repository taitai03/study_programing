# プログラミング学習Webアプリ 要件定義

> ステータス: 要件ヒアリング中（未決事項あり）
> 最終更新: 2026-10-19

## 1. 決定事項

### 1.1 背景

プロジェクトを開始するにあたり、各個人のプログラミング能力と知識を向上させる。

### 1.2 対象者（レベル区分）

| レベル | 定義 |
| --- | --- |
| 初級 | まったく何も学んだことのない初学者 |
| 中級 | 書いてある処理は読めるが、自分の力で書くことはできない |
| 上級 | リファクタリングや安全な設計ができ、プロダクト全体の責任者を目指す |

### 1.3 アプリの内容

- プログラミングを学べる **Webアプリケーション** である
- 上記の対象者（初級／中級／上級）でコンテンツを **ジャンル分け** する
- **実際の現場で使える** 学びを得られる内容にする
- **実際に手を動かしながら** 学べる
- 対象言語は次の3つ
  - Swift
  - JavaScript（TypeScript）
  - Ruby（Rails）

### 1.4 利用者・認証

- 利用者は **社内メンバーのみ**
- **ログインあり**。認証は **GitHubログイン**
- 学習の進捗はユーザーごとに記録する

### 1.5 学習体験

- コードは **サーバー側のサンドボックスで実行** する（3言語ともブラウザから実行できるようにする）
- 正誤判定は **自動テスト＋AIレビュー**
  - 初級・中級: テストケースによる自動判定
  - 上級（設計・リファクタリング課題）: AI（Claude）によるコードレビューでフィードバック

### 1.6 スコープ

- MVPは **3言語 × 全レベル（初級／中級／上級）**

### 1.7 技術・インフラ

- アプリ: **Next.js ＋ TypeScript**
- デプロイ先: **Vercel**
- 教材・課題・テストケース: **リポジトリ内のMarkdownで管理**（追加・修正はPRで行う）

## 2. 相談中の事項

### 2.1 データの持ち方

教材と、ユーザーが生み出すデータを分けて考える案。

| データ | 置き場所（案） | 理由 |
| --- | --- | --- |
| レッスン本文・課題文・ヒント | リポジトリ内のMarkdown（frontmatterにレベル・言語などのメタ情報） | 決定済み。PRでレビューでき、変更履歴が残る |
| 課題の初期コード・テストケース・模範解答 | リポジトリ内のファイル（課題ごとのディレクトリ） | 教材と一緒にバージョン管理できる |
| ユーザー、進捗、提出コード、判定結果、AIレビュー結果 | マネージドPostgreSQL（Vercel Marketplaceの Neon または Supabase）＋ ORM（Drizzle または Prisma） | Vercelと連携しやすく、無料枠から始められる |

### 2.2 コード実行サーバー（サンドボックス）

Vercelのサーバーレス関数ではSwiftやRubyを安全に実行できないため、実行環境は別に用意する必要がある。

- 案A: Judge0（OSSのコード実行エンジン）をFly.ioやVPSにセルフホストする
- 案B: 言語ごとのDockerイメージを使う自前の実行サーバーをFly.ioやCloud Runに置く（Railsのように複数ファイル＋テストが必要な課題に対応しやすい）
- 制約: Linux上のSwiftではSwiftUI／UIKitが動かない。サーバー実行ではSwiftの言語仕様やロジックの演習に限られ、iOS固有の内容は別の扱いが必要
