# プログラミング学習Webアプリ 要件定義

> ステータス: 要件確定（設計上の未決事項は architecture.md を参照）
> 最終更新: 2026-10-19

## 1. 決定事項

### 1.1 背景

プロジェクトを開始するにあたり、各個人のプログラミング能力と知識を向上させる。

### 1.2 対象者（レベル区分）

| レベル | 定義 |
| --- | --- |
| 初級 | まったく何も学んだことのない初学者 |
| 中級 | 書いてある処理は読めるが、自分の力で書くことはできない |
| 上級 | リファクタリングや安全な設計ができ、プロダクト全体の責任者を目指す |

### 1.3 アプリの内容

- プログラミングを学べる **Webアプリケーション** である
- 上記の対象者（初級／中級／上級）でコンテンツを **ジャンル分け** する
- **実際の現場で使える** 学びを得られる内容にする
  - ゴールは、業務で仕様を渡されたら **自分でコードを書ける** 状態になること。プログラミングの勉強のためのプログラミングにはしない
  - 題材はすべて業務（架空のECショップ「さくらマート」）にし、課題は業務のチケット形式で出す
- **実際に手を動かしながら** 学べる
- 対象言語は次の3つ
  - Swift
  - JavaScript（TypeScript）
  - Ruby（Rails）

### 1.4 利用者・認証

- 利用者は **社内メンバーのみ**、**10人程度**
- **ログインあり**。認証は **GitHubログイン**
- ログインできるのは、管理者が **許可リストに登録したGitHubユーザーだけ**
- レベル（コース）は **本人が選ぶ**。各コースの入口に前提のチェックリストを置く
- メンター・管理者向けに **進捗一覧とユーザー管理の画面** を作る。メンターは受講者のPRの差分をアプリ上で見られる
- 学習の進捗はユーザーごとに記録する

### 1.5 学習体験

- 受講者は **全員Macを持っている**
- 各レッスンは **テキスト（短い解説）＋ 演習 ＋ 確認クイズ（3問程度）** で、1レッスン30〜60分を想定する
- 初級（JS/TS、Ruby）: **ブラウザ内で実行** して、自動で判定する
- 初級（Swift）: **Xcode（Playground）で解き**、アプリ上のクイズで理解を確認する
- 初級の最後に、環境構築とGit／GitHubのレッスンを置く
- 中級・上級: **ローカルで解いてPRを出し、GitHub Actionsのテストで判定** する
  - 課題リポジトリは **受講者の個人アカウント** に作る
  - リポジトリの単位は **受講者 × コースで1つ**（1課題 ＝ 1PR）
  - リポジトリは **private**
- 上級: テストに加えて **AI（Claude）がPRをレビュー** する
  - APIキーは当面 **開発者個人のキー** を使い、本格運用の前に会社のキーへ切り替える。回数上限を設ける
- 上級の演習は次の4種類
  - **問題のあるコードの改善**: 動くが設計に問題のあるコードを、テストを通したままリファクタリングする
  - **脆弱性の修正**: SQLインジェクションや認可漏れなどを含むコードを直す。攻撃を再現するテストで判定する
  - **機能追加を設計から**: 仕様だけ渡して機能を追加させ、設計方針をPRの説明に書かせる。AIが評価する
  - **コードレビュー演習**: テンプレートに用意したPRをレビューして指摘を書く。指摘の質をAIが評価する
- iOS固有の課題: **ロジックはLinuxランナーでテストし、画面部分はAIレビューのみ**
- コード実行サーバーは持たない

詳細は [architecture.md](architecture.md) を参照。

### 1.6 スコープ

- MVPは **3言語 × 全レベル（初級／中級／上級）**
- 1コースあたり **8〜10レッスン**（共通の「開発の準備」5本を含め、全83本。内訳は [curriculum.md](curriculum.md)）
- 教材は **Claudeが下書きし、社内メンバーがPRでレビュー** する

### 1.7 技術・インフラ

- アプリ: **Next.js ＋ TypeScript**
- デプロイ先: **Vercel**
- 教材・課題・テストケース: **リポジトリ内のMarkdownで管理**（追加・修正はPRで行う）

### 1.8 データの持ち方

- 教材・課題・テストケース: このリポジトリと、コースごとのテンプレートリポジトリ
- ユーザー、進捗、提出結果、AIレビュー結果: PostgreSQL（Neon）＋ Drizzle ORM

### 1.9 進捗・モチベーション

- コースごとの **達成率**（ダッシュボードに言語 × レベルで表示）
- **学習の足あと**（GitHubの草のような、日ごとの活動カレンダー）
- **バッジ・修了証**（コース修了でバッジを付与し、プロフィールに表示）
- **ランキング**（完了したレッスン数など）

### 1.10 予算

- インフラは **無料プランの範囲** で運用し、費用がかかるのはClaude APIだけにする
- ※ 要確認: Vercelの無料プラン（Hobby）は個人・非商用の利用に限られている。社内研修での利用がこれに当たるかを確認し、当たる場合はProプランにするか、別のデプロイ先を検討する

### 1.11 デザイン・その他

- デザインは **シンプルな学習サービス風**（shadcn/ui ＋ Tailwind CSS、読みやすさ重視、ダークモード対応）
- **PCのみ** 対応（スマホ表示は考慮しない）
- UIは **日本語のみ**

### 1.12 スケジュール

**なるべく早く使い始められるよう、段階的に公開する。** 最終的なゴールは3言語 × 全レベルで、そこまでを次の順で進める。

| マイルストーン | 内容 | 使えるようになること |
| --- | --- | --- |
| M1 | アプリの土台（ログイン、許可リスト、教材表示、進捗）＋ TypeScript初級 | TypeScript初級をブラウザで学べる |
| M2 | Ruby初級（ruby.wasm）＋ Swift初級（Playground＋クイズ）＋ 環境構築・Gitのレッスン | 全言語の初級を学べる |
| M3 | GitHub App連携、PR判定、メンター画面 ＋ 3言語の中級 | 中級をPRで学べる |
| M4 | AIレビュー ＋ 3言語の上級 | 上級を学べる |
| M5 | 達成率以外の進捗表示（足あと、バッジ、ランキング） | モチベーション機能 |

- 達成率はM1から表示する
- 各マイルストーンが終わった時点で、受講者に使ってもらい始める
