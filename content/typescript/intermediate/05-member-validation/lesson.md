## 入力は必ずサーバーで確かめる

画面のフォームで「必須」にしていても、APIは誰でも直接呼び出せます（`curl` や、改造したアプリから）。**サーバーに届いた入力は、ブラウザ側のチェックをすり抜けている前提で、必ずサーバーでもう一度確かめます**。

チェックしないとどうなるか:

- 名前が空の会員や、`<script>` を含む名前の会員が登録される
- 形式の違うメールアドレスが入り、メールが届かない
- 想定外の型（数値の代わりに文字列など）で、あとの処理が落ちる（500エラー）

## zod でスキーマを書く

**zod** は「データの形と条件（スキーマ）」を書いて、入力を確かめるライブラリです。確かめた結果には、自動で TypeScript の型が付きます。

```ts
import { z } from "zod";

const memberInputSchema = z.object({
  name: z.string().trim().min(1, "名前を入力してください").max(50, "名前は50文字以内で入力してください"),
  email: z.string().trim().toLowerCase().pipe(z.email("メールアドレスの形式が正しくありません")),
});

type MemberInput = z.infer<typeof memberInputSchema>; // { name: string; email: string }
```

| 書き方 | 意味 |
| --- | --- |
| `.trim()` / `.toLowerCase()` | 確かめる前に値を整える（前後の空白を取る、小文字にする） |
| `.min(1, "メッセージ")` | 条件と、満たさないときのメッセージ |
| `.pipe(z.email())` | 整えた値を、次のスキーマで確かめる |
| `z.infer<typeof schema>` | スキーマから型を作る |

### parse と safeParse

```ts
const result = memberInputSchema.safeParse(body);
if (!result.success) {
  result.error.issues; // [{ path: ["email"], message: "メールアドレスの形式が正しくありません" }, ...]
} else {
  result.data; // 整えたあとの値（型は MemberInput）
}
```

`parse` は失敗すると例外を投げ、`safeParse` は結果を値で返します。APIでは、エラーを 400 のレスポンスに変えたいので `safeParse` が扱いやすいです。

## エラーのレスポンスを設計する

APIのエラーは、**呼び出す側（画面）が次に何をすればいいか分かる** ように返します。

| 状況 | ステータス | 例 |
| --- | --- | --- |
| 入力が正しくない | 400 Bad Request | 項目ごとのメッセージを返し、画面で入力欄の下に表示できるようにする |
| 認証されていない | 401 Unauthorized | |
| すでにある（重複） | 409 Conflict | 「このメールアドレスはすでに登録されています」 |
| サーバーの問題 | 500 Internal Server Error | 詳しい原因は返さない |

```json
{ "error": "入力内容に誤りがあります", "fields": { "email": "メールアドレスの形式が正しくありません" } }
```

形を揃えておく（いつも `error` がある、など）と、画面側の処理がシンプルになります。

## ユーザー向けのメッセージと、開発者向けのログ

予期しないエラー（DBにつながらない、など）のとき、エラーの詳細（SQL やスタックトレース）をそのままユーザーに返してはいけません。**攻撃の手がかりになり、ユーザーにとっても意味がありません**。

- **ユーザー向け**: 何が起きたかと、次にどうすればいいか（「時間をおいて試してください」）
- **開発者向け（ログ）**: 原因を調べるための詳細（`console.error` やログの仕組みに出す）

```ts
try {
  // ...
} catch (e) {
  console.error("会員登録に失敗しました", e); // 開発者向け
  return Response.json({ error: "会員登録に失敗しました。時間をおいて試してください" }, { status: 500 });
}
```

## 重複のチェック

「同じメールアドレスは登録できない」のチェックは、入力の形のチェックとは別に、**DBを見て** 行います。大文字・小文字の違いで別のアドレスとして登録されないよう、保存する前に形を揃えておく（小文字にする）のがポイントです。さらに、DBの一意制約（`unique`）も付けておくと、同時に登録された場合でも重複を防げます。
