## Git とは

**Git** は、ファイルの変更の履歴を記録するツールです。「いつ・誰が・何を・なぜ変えたか」を残しておけるので、次のようなことができます。

- 前の状態に戻す（変更で壊れたとき）
- 何を変えたのかを見比べる（レビューのとき）
- 複数の人が、同じプロジェクトを同時に変更する（ブランチ）

チームでの開発では、Git を使わないことはまずありません。

## 変更を記録する流れ

Git では、変更を次の3つの段階で扱います。

| 段階 | 意味 | 移すコマンド |
| --- | --- | --- |
| 作業ツリー | ファイルを編集した状態 | （ファイルを編集する） |
| ステージ | 次の記録に含める変更を選んだ状態 | `git add` |
| コミット | 履歴として記録した状態 | `git commit` |

```bash
git status                 # 今の状態を確認する（迷ったらまずこれ）
git diff                   # まだステージしていない変更の中身を見る
git add src/cart.ts        # 記録に含めるファイルを選ぶ
git diff --staged          # ステージした変更の中身を見る
git commit -m "かごが空のときは送料を0円にする"
git log --oneline          # 履歴を見る
```

### 意味のある単位で commit する

commit は、**1つの目的の変更ごと** に分けます。

- よい例: 「かごが空のときは送料を0円にする」「送料の計算のテストを追加する」
- よくない例: 「いろいろ修正」「作業中」（何が変わったか分からない）、送料の修正と関係ない名前の変更を1つの commit に混ぜる

commit を分けておくと、問題が起きたときに原因の commit を見つけやすく、その commit だけを取り消すこともできます。

**commit メッセージ** には「何をしたか」を、必要なら「なぜしたか」も書きます。あとで履歴を読む人（未来の自分も含む）のための説明です。

### 差分（diff）の読み方

```diff
   def shipping_fee
-    return 0 if total_with_tax > 5000
+    return 0 if total_with_tax >= 5000
     SHIPPING_FEE
   end
```

`-` で始まる行が削除した行、`+` で始まる行が追加した行です。commit する前に `git diff` で、**意図しない変更が混ざっていないか** を必ず確認しましょう。

## ブランチ: 作業の流れを分ける

**ブランチ** は、履歴を枝分かれさせる仕組みです。新しい機能や修正は、`main` ブランチに直接 commit せず、作業用のブランチを作って行います。

```bash
git switch -c fix/free-shipping   # 新しいブランチを作って移動する
# 編集して commit する
git switch main                    # main に戻る
git branch                         # ブランチの一覧（* が今いるブランチ）
```

ブランチを分けておけば、作業の途中でも `main` は動く状態のままです。作業が終わったら、レビューを受けてから `main` に取り込みます（次のレッスンで学びます）。

## 共有しないファイル: `.gitignore`

次のようなファイルは、Git で記録・共有しません。

- `.env` など、パスワードや API キーが書かれたファイル
- `node_modules/` など、コマンドで作り直せるファイル
- `.DS_Store` など、PC ごとの設定ファイル

`.gitignore` というファイルに書いたパターンに当てはまるファイルは、Git が無視します。

```text
.env
node_modules/
.DS_Store
```

**パスワードや API キーを一度 commit して GitHub に push すると、あとから消しても履歴に残ります**。間違えて push してしまったら、すぐにメンターに報告してください（キーを無効にする必要があります）。

## やり直し方

| やりたいこと | コマンド |
| --- | --- |
| まだステージしていないファイルの変更を取り消す | `git restore ファイル名` |
| ステージを取り消す（変更は残す） | `git restore --staged ファイル名` |
| commit した変更を打ち消す commit を作る | `git revert コミットID` |

`git restore` で取り消した変更は元に戻せないので、`git diff` で中身を確認してから実行します。

すでに共有した（push した）commit を取り消すときは、履歴を書き換えずに、**打ち消す commit を新しく作る** `git revert` を使います。ほかの人が同じ履歴を使っているからです。

## やってみよう

1. 前のレッスンで作った `~/projects/sakura-mart` に移動して、`git init` で Git を使い始める
2. `README.md` に1行書いて、`git add` と `git commit` で記録する
3. `git switch -c docs/add-rules` でブランチを作り、`docs/rules.md` に送料のルールを書いて commit する
4. `.env` というファイルを作り、`.gitignore` に `.env` と書いて、`git status` に `.env` が出てこないことを確認する
5. `git log --oneline` で履歴を確認する
