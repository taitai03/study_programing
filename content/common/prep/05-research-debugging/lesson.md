## 調べる力は、書く力と同じくらい大事

現場のエンジニアも、すべてを覚えているわけではありません。毎日、ドキュメントを読み、エラーを調べ、デバッガで動きを確かめながら書いています。**分からないことを、自分で調べて解決する方法** を身に付けましょう。

## 公式ドキュメントを読む

言語やライブラリの使い方は、まず **公式ドキュメント** で調べます。個人のブログや記事は、古いバージョンの情報だったり、間違っていたりすることがあります。

| 調べたいこと | 公式ドキュメント |
| --- | --- |
| JavaScript の標準の機能 | MDN Web Docs |
| TypeScript | TypeScript Handbook |
| Next.js / React | Next.js Docs、react.dev |
| Ruby / Rails | Ruby リファレンスマニュアル、Rails ガイド |
| Swift / iOS | The Swift Programming Language、Apple Developer Documentation |

ドキュメントを読むときのコツ:

1. **バージョンを確認する**: プロジェクトで使っているバージョンのドキュメントを読む（`package.json` や `Gemfile.lock` で確認できる）
2. **サンプルコードから読む**: 説明の文章より先に、例のコードを見ると全体がつかみやすい
3. **引数と戻り値を確認する**: 何を渡すと何が返るのか。`nil` や `null` が返ることはあるか

## エラーメッセージで調べる

エラーが出たら、まずメッセージを読みます（各言語の初級のレッスン1でやったとおりです）。それでも分からなければ、検索します。

- エラーメッセージの **固有の部分** で検索する。自分の変数名やファイル名は取り除く
  - 例: `undefined method 'name' for nil` で検索する（`order.customer` のような自分のコードの部分は入れない）
- 言語やライブラリの名前を付ける（`Rails`、`Next.js` など）
- 検索結果は、**日付とバージョン** を確認する

## デバッグ: 原因を絞り込む

**デバッグ** は、バグの原因を見つけて直す作業です。闇雲にコードを書き換えるのではなく、次の手順で原因を絞り込みます。

1. **再現する**: どんな操作・データのときに起きるかを確かめ、確実に起こせるようにする
2. **予想と実際を比べる**: 「この時点で変数はこの値のはず」という予想と、実際の値を比べる
3. **範囲を狭める**: 予想と実際がずれ始める場所を探す
4. **直して確かめる**: 直したら、同じ手順で起きなくなったことと、ほかが壊れていないこと（テスト）を確かめる

### 値を表示して確かめる

いちばん手軽なのは、途中の値を表示することです（`console.log`、`p`、`print`）。確認が終わったら、表示のコードは消しておきます。

### ブレークポイントを使う

**デバッガ** を使うと、プログラムを好きな場所で一時停止して、その時点のすべての変数の値を見られます。

- VS Code: 行番号の左をクリックすると赤い丸（**ブレークポイント**）が付く。デバッグ実行するとそこで止まる
- Xcode: 行番号をクリックすると青い印が付く
- Ruby: コードに `binding.irb` や `debugger` と書くと、そこで止まる

止まったら、次のことができます。

| 操作 | 意味 |
| --- | --- |
| 変数の値を見る | その時点での値を確認する |
| ステップオーバー | 1行ずつ実行する |
| ステップイン | 呼び出している関数の中に入る |
| 続行 | 次のブレークポイントまで進める |

`console.log` を何度も書いては消すより、ブレークポイントで止めて値を見るほうが速いことがよくあります。

## AIツールとの付き合い方

ChatGPT や Claude、GitHub Copilot などの AI ツールは、エラーの意味を聞いたり、書き方の例を見たりするのにとても便利です。ただし、次のことを守ってください。

### 答えを鵜呑みにしない

- AI の答えは **間違っていることがあります**。存在しないメソッドや、古いバージョンの書き方を、自信のある口調で答えることもあります
- 出てきたコードは、**自分で読んで理解してから** 使う。理解できないコードは使わない
- 公式ドキュメントで確認し、実際に動かして、テストで確かめる
- 学習中は、まず自分で考えてから AI に聞く。答えだけを写すと、自分で書ける力が身に付きません

### 社外秘の情報を貼らない

- 会社のソースコード、お客様の個人情報、パスワード、API キー、社内の資料などを、**会社が許可していない AI ツールに貼り付けてはいけません**
- 入力した内容が、サービスの提供元に保存されたり、学習に使われたりすることがあるためです
- どのツールを、どの範囲で使ってよいかは、会社のルールを確認してください。分からないときは、貼る前にメンターに聞きましょう

## 質問のしかた

自分で調べても解決しないときは、ためらわずに質問しましょう。30分調べても進まないなら、聞くタイミングです。質問するときは、次の4つをそろえます。

1. **やりたいこと**: 何をしようとしているか
2. **起きていること**: 実行したコマンドや操作と、エラーメッセージの全文
3. **期待していること**: 本当はどうなってほしいか
4. **試したこと**: 調べたこと、試してだめだったこと

## やってみよう

1. 自分のコースの言語で、初級で使ったメソッド（`map`、`sum` など）を公式ドキュメントで探して読む
2. 初級の演習のコードを VS Code（または Xcode）で開き、ブレークポイントを置いて、変数の値を確認しながら1行ずつ実行する
3. 会社の AI ツールの利用ルールを確認する
