## プログラムは上から順に実行される

プログラムは、コンピューターへの指示を並べたものです。書いた指示は **上から順番に** 実行されます。

```ruby
puts "さくらマートへようこそ"
puts 1000 + 500
```

`puts` は、うしろに書いた値を「出力」に表示する命令です。実行すると、次のように表示されます。

```text
さくらマートへようこそ
1500
```

- `"さくらマートへようこそ"` のように `"` で囲んだものは **文字列**（文章）です
- `1000 + 500` のように囲まないものは **数値** で、計算ができます
- Rubyでは、1行に1つの命令を書きます。行の終わりに `;` は要りません

右のエディタの「実行」ボタンを押すと、書いたコードが実行されて、下の「出力」に結果が出ます。

### `puts` と `p`

値を確かめるときには、`p` もよく使います。

```ruby
puts "550"  # => 550
p "550"     # => "550"
p 550       # => 550
```

`p` は、値を **Rubyのコードに近い形** で表示します。文字列なら `"` が付くので、「数値の550」なのか「文字列の"550"」なのかを見分けられます。動作を確かめるとき（デバッグ）は `p` が便利です。

`#` から行の終わりまでは **コメント** です。実行されないので、メモや説明を書くのに使います。

## エラーは「どこで」「何が」起きたかを教えてくれる

プログラムを書いていると、必ずエラーに出会います。エラーは失敗ではなく、**コンピューターが問題の場所を教えてくれている** ものです。現場のエンジニアも、毎日エラーメッセージを読んで直しています。

たとえば、次のコードを実行すると、

```ruby
price = 1000
puts prise
```

次のようなエラーが出ます。

```text
NameError: undefined local variable or method 'prise' for main（2行目）
```

エラーメッセージは3つの部分に分けて読みます。

| 部分 | 例 | 意味 |
| --- | --- | --- |
| エラーの種類 | `NameError` | 存在しない名前を使った |
| メッセージ | `undefined local variable or method 'prise'` | `prise` という変数やメソッドは定義されていない |
| 場所 | `2行目` | 2行目で起きた |

2行目を見ると、`price` と書くべきところを `prise` と書いていることが分かります。

### よく出会うエラー

| エラー | よくある原因 |
| --- | --- |
| `NameError: undefined local variable or method 'xxx'` | 変数やメソッドの名前のタイプミス。定義する前に使っている |
| `NameError: uninitialized constant XXX` | 大文字で始まる名前（定数）のタイプミス |
| `NoMethodError: undefined method 'xxx'` | メソッドの名前のタイプミス。その値では使えないメソッドを呼んでいる |
| `SyntaxError` | `end` の書き忘れや、`"` の閉じ忘れなど、書き方の間違い |
| `TypeError` | 文字列と数値を `+` でつなぐなど、組み合わせられない値を使っている |

`SyntaxError` のときは、どこがおかしいかを `^` の印で示してくれます。ただし、本当の原因（たとえば `end` の書き忘れ）は、印の場所より **前の行** にあることが多いので、少しさかのぼって確認しましょう。

## エラーを直すときの手順

1. エラーメッセージの **場所（行番号）** を見る
2. **メッセージ** を読んで、何が起きたかを考える（英語でも、単語を拾えば意外と分かります）
3. 直して、もう一度実行する。別のエラーが出たら、また1から

一度に全部を理解する必要はありません。演習では、まだ学んでいない書き方（`def` や `if`）も出てきますが、今は「エラーを手がかりに直す」ことに集中してください。
